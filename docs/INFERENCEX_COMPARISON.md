# InferenceX data on the Benchmark comparison page

The Benchmark comparison page treats InferenceX as a separate measured source. It expands the filter options even when the Red Hat Hugging Face benchmark dataset has no rows for a model or GPU. A runtime selection returns measurements from its own source only; the two measured sources are not automatically overlaid because they use different benchmark clients. Every simulator in the catalog that supports the selected model, GPU, and serving backend predicts at the selected source's measured concurrency levels. A simulator that cannot model the run, including a disaggregated topology its release does not support, is skipped with a reason; its measured results remain available without a predicted series.

Serving backend and backend version are shared across the two measured sources and are owned by Settings. For vLLM releases, labels such as the Red Hat dataset's `vLLM-0.24.0` and InferenceX's `v0.24.0` appear as one `v0.24.0` option. A Settings pin written as a catalog literal (`0.24.0`) is canonicalized to the measured label before matching, so an explicit choice is not reported as missing. The same applies to non-vLLM backends: a bare catalog pin such as SGLang `0.5.14` satisfies a measured vendor build of that release, such as `v0.5.14-rocm720-mi35x`, while two specific builds of one release remain distinct. The measured runtime configuration retains the source, precision, and benchmark release; choosing a serving version does not imply both sources measured the same workload. An explicit version pin that matches no measured rows produces an empty state linking to Settings. Leaving the version at the simulator default uses the newest measured release for the selected backend and GPU and reports that choice in the page notice.

Prediction assumptions default to the selected measured run's serving mode and precision. Pipeline, data, and expert parallelism are not recorded by the benchmark, so they default to the simulator's own resolution and require an explicit override to change. Disaggregated InferenceX rows also record prefill and decode tensor-parallel widths and worker counts; predictions use that measured pool shape rather than reusing the decode width for both pools. The measured release is sent to a simulator only when its catalog lists that release for the GPU; otherwise the field is omitted and the service resolves its own default. Each predicted series is labeled with the simulator and version that actually produced it, and percentage differences are hidden when the resolved version, serving mode, measured pool shape, or assumptions differ from the measurement.

The private Hugging Face dataset [`redhat-performance/configiq-inferencex-comparison`](https://huggingface.co/datasets/redhat-performance/configiq-inferencex-comparison) holds `inferencex-8k1k.json`: public single-turn 8,192 input / 1,024 output token results for models in ConfigIQ's approved-model list (`approvedModels` in `public/config.json`) with a verified InferenceX model ID mapping. This is InferenceX's currently active fixed-length scenario; its 1k/1k and 1k/8k scenarios are deprecated. The page shows the selected measurement date and links to its source run.

The page attributes this benchmark data to SemiAnalysis InferenceX and links to the source and selected run. An [InferenceX collaborator confirmed this attribution requirement](https://github.com/SemiAnalysisAI/InferenceX/issues/4655#issuecomment-6507892332) in response to the proposed private storage, public display, and weekly refresh workflow.

The ConfigIQ server reads this file with `INFERENCEX_HF_TOKEN`, which must be a Hugging Face token with read access to that private dataset. Set it in the local or deployment server environment; never expose it through a `NEXT_PUBLIC_` variable or browser request. The server caches a validated snapshot for five minutes and serves the last successful copy if a later HF request fails. If the token is absent or the dataset cannot be loaded at startup, the Red Hat benchmark data remains available and the page shows an InferenceX warning. The private dataset controls storage access, but measured results returned by ConfigIQ's comparison API remain visible to users of that page.

Publish a fresh snapshot from the public InferenceX API with one manual command:

```bash
uv run --group tested-models python scripts/publish-inferencex-snapshot.py
```

The collector discovers models from `/api/v1/availability` and `/api/v1/views/options`, intersects them with the verified approved-model mappings, then fetches matching display models from `/api/v1/benchmarks`. The publisher validates the results again, confirms the HF dataset is private, and uploads the JSON directly from memory when measurements change. A local run requires an HF login with write access to that dataset. No snapshot file is written to the ConfigIQ checkout. The browser reads ConfigIQ's same-origin comparison API; it does not call InferenceX or the private HF dataset directly.

The `refresh-inferencex` job in `.github/workflows/publish-performance-data.yml` runs every Monday at 00:00 `America/New_York` when `INFERENCEX_PUBLISH_ENABLED=true`. It can also run through `workflow_dispatch` on `main` with `publish_inferencex=true`; an InferenceX-only manual run skips the S3 job. The job uses a write-enabled Hugging Face Trusted Publisher scoped to this workflow, `main`, and the private dataset. It does not use the S3 read role or a stored HF write token.

InferenceX response times are seconds; the snapshot converts TTFT and TPOT to the milliseconds expected by the internal aggregation code. `output_tput_per_gpu` is per physical chip, so aggregate throughput multiplies it by the physical GPU count, adding prefill and decode counts only for disaggregated runs. Disaggregated rows are rejected unless the prefill tensor-parallel size and prefill GPU count are present, so aggregate throughput cannot be undercounted. `tp` remains the decode tensor-parallel size, and `tp_prefill` preserves the prefill size for disaggregated runs. The runtime selector keeps backend, image version, precision, speculation, topology, offload mode, and curve separate so unlike runs are not averaged together.

The approved-model filter limits which models enter the snapshot; it does not guarantee every simulator supports the selected GPU, serving backend, or version. Models outside the approved list are excluded, even if InferenceX publishes measurements for them. InferenceX, the Red Hat benchmark, and each simulator may use different request-length distributions, runtime settings, and serving topologies, so the plotted difference is diagnostic rather than a like-for-like accuracy score.

Sources: [InferenceX API reference](https://inferencex.semianalysis.com/api), [InferenceX scenario policy](https://github.com/SemiAnalysisAI/InferenceX/blob/main/inferencex-e2e/docs/MODELS.md).
