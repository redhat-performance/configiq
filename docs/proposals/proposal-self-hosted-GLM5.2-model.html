Proposal: Self-Hosted GLM 5.2 Model Pilot Proposal on IBM Cloud H200 Infrastructure

Author: Ashish Kamra, Yuchen Fama

Date: July 25, 2026

Requested Budget: ~$560K over 6 months

Proposed Solution

Deploy a gated pilot of self-hosted "frontier category" open-weight model inference on IBM Cloud, starting with GLM 5.2 FP8, serving Red Hat engineering workloads through a production-grade llm-d + OpenShift stack. This is not a broad rollout — it is a controlled pilot to generate the performance data, cost model, and operational playbook needed for an informed scale decision.

Serving Stack

The deployment leverages llm-d with its full feature set: cache-aware request routing, prefill/decode disaggregation, wideEP deployment, and KV-cache offload to CPU memory (1.7 TB per node) and CephFS on NVMe. This is the same stack Red Hat markets to customers.

Capacity

Benchmarking on the InferenceX agentic workload dataset (SemiAnalysis CC-Traces Weka) shows 64 H200 GPUs comfortably handle 128 concurrent agent session trees at 32 tokens/sec/user E2E throughput — well above the 30 tok/s threshold generally accepted as good interactive experience. The aggregate cluster output throughput at this concurrency is 6,000 tokens/sec.

A "concurrent session tree" in this benchmark is a full multi-turn coding agent conversation (root agent plus any spawned subagents), replayed with realistic inter-turn think times from recorded traces. This maps to active developer usage as follows:

The value proposition is not 1:1 replacement but providing a capable, cost-effective option for the many workloads where an open-weight model is sufficient. Additionally, self-hosted inference eliminates per-token variable cost entirely — once the infrastructure is provisioned, there are no incremental charges for heavier usage, which de-risks adoption and removes quota friction for developers.

Strategic Value Beyond Cost

Agentic SDLC acceleration. Developers using Claude Code and OpenCode get an uncapped, high-throughput model endpoint without monthly quota constraints. This removes friction from the fastest-growing category of internal AI usage.

Autonomous pipeline enablement. Agentic CI/CD pipelines consume tokens continuously and don't require human model selection. Once a harness is tuned against a model, it drives traffic predictably — ideal for self-hosted economics where higher utilization improves unit cost.

Customer-facing credibility. Running our own inference stack (llm-d on OpenShift on IBM Cloud H200) at production scale gives product, sales, and engineering teams first-party operational data. This is the deployment pattern we ask customers to adopt.

Product validation. The pilot will stress-test llm-d features (disaggregated serving, KV-cache offload, wideEP) under real heterogeneous workloads, feeding optimization insights back into engineering. The PSAP team is already investing heavily in GLM 5.2 serving optimization for customers via Dynamo and SGLang — this pilot creates an internal feedback loop.

Model optionality. The infrastructure is not model-specific. The same H200 cluster can serve other open-weight models (e.g., Nemotron 3 Ultra for US-only use cases) as they become available and are cleared by legal review, building a platform rather than a point solution.

Known Considerations

Model provenance. GLM 5.2's origin requires a legal and geopolitical review before production use. We understand this review is already underway separately. The self-hosted deployment model mitigates data-residency concerns: all data remains within Red Hat's IBM Cloud VPC, with no external API calls or data transmission to model providers.

Legal review. A business and legal review of open-weight model implications for production work is required. We recommend this proceed in parallel with infrastructure provisioning to avoid sequential delays.

Performance optimization. Current benchmarking numbers represent a baseline. The PSAP team's active optimization work on GLM 5.2 serving will continue to improve throughput and reduce per-token costs over the pilot period.

Ask

  1. Approve ~$560K in IBM Cloud infrastructure spend for a 6-month pilot (8 x 8xH200 nodes + 3 control plane nodes).
  2. Designate pilot user cohorts from Agentic SDLC teams and autonomous pipeline teams to drive utilization and provide feedback.
  3. Initiate parallel legal review of GLM 5.2 (and Nemotron 3 Ultra) for internal production use.
  4. Commit to a go/no-go review at month 3 using utilization, performance, and cost-per-token data to decide whether to scale, pivot models, or wind down.
